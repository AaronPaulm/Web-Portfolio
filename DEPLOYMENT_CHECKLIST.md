# Portfolio deployment checklist

The portfolio is a static HTML, CSS, and JavaScript site. Complete the items below before sharing it publicly.

## Before launch

- [ ] Replace the APM initials artwork with a real, optimized photo, or keep it if you prefer not to publish a photo.
- [x] Add your email address and GitHub profile link.
- [x] Add a contact form that opens a prefilled email in the visitor's email app. For direct website submissions, connect a form service or backend.
- [ ] Add accurate education details if you want an education section (school, program, and dates).
- [x] Add project titles, project summaries, technology stacks, and COLM site/repository links.
- [x] Add project screenshots and technology stacks for both projects. Replace the images in `assets/img/` whenever you want to update the previews.
- [ ] Add details about your specific contributions to the Order and Queue Management System.
- [ ] Add a resume only if you have a current PDF; verify the filename and link before publishing.
- [ ] Review the biography and skill list. Keep only technologies you can discuss confidently, and describe your experience level honestly.
- [ ] Choose a static host (for example GitHub Pages, Netlify, or Cloudflare Pages) and publish the site files from the repository root.
- [ ] Test the deployed URL on a phone and desktop. Check navigation, theme toggle, images, external links, and browser console for errors.
- [ ] Confirm the hosting setup provides HTTPS. If using a custom domain, configure DNS and verify the domain after deployment.

## After launch

- [ ] Add a custom domain, if desired, and update the browser title, description, and social-sharing preview for that URL.
- [ ] Check keyboard navigation, color contrast, image alt text, and reduced-motion behavior.
- [ ] Re-test every project and contact link whenever you update the site.
- [ ] Keep project details and resume current; remove projects or links that are no longer available.
